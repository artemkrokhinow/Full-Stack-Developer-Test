# ЖЕСТКИЕ ПРАВИЛА ФРОНТЕНДА (REACT + TYPESCRIPT)

Действуй как Senior Frontend Architect. При генерации или ревью клиентского кода строго соблюдай следующие архитектурные стандарты:

## 1. АСИНХРОННОСТЬ И POLLING (ЗАЩИТА ОТ УТЕЧЕК И DDOS)

- **ЗАПРЕЩЕНО:** Использовать `setInterval` для сетевых запросов. При сетевых задержках это приводит к наслоению запросов и лавинообразной перегрузке бэкенда.
- **ОБЯЗАТЕЛЬНО:** Использовать рекурсивный `setTimeout` для поллинга, который запускает следующий цикл ТОЛЬКО после полного завершения предыдущего запроса (через блок `finally`).
- **ОЧИСТКА (CLEANUP):** Любой хук `useEffect`, инициализирующий таймеры или сетевые подписки, ОБЯЗАН возвращать функцию очистки (`clearTimeout`, `clearInterval`, `controller.abort()`). Игнорирование этого правила ведет к утечкам памяти при размонтировании компонента [1].

## 2. УПРАВЛЕНИЕ СОСТОЯНИЕМ (STATE MANAGEMENT)

- **ЗАПРЕЩЕНО:** Использовать разрозненные булевы флаги (например, `isLoading`, `isError`, `data` одновременно в одном объекте). Это порождает невалидные состояния (например, `isLoading: true` и `isError: true` одновременно) [2, 3].
- **ОБЯЗАТЕЛЬНО:** Применять паттерн «Размеченное объединение» (Discriminated Union) для описания дискретных состояний. Состояние сетевого запроса должно явно моделироваться как конечный автомат: `RequestPending | RequestError | RequestSuccess` [4, 5].

## 3. СЕТЕВЫЕ СБОИ И ТАЙМАУТЫ (RESILIENCY)

- **ЗАПРЕЩЕНО:** Оставлять `fetch` без таймаутов. Браузерный `fetch` по умолчанию может висеть минутами, блокируя UI [6].
- **ОБЯЗАТЕЛЬНО:** Оборачивать каждый сетевой вызов в механизмы контроля времени с использованием `AbortController`.
- **ОБРАБОТКА ОШИБОК:** При перехвате `AbortError` интерфейс должен корректно переходить в состояние сетевого сбоя с возможностью повторной попытки (retry).

## 4. ЧИСТАЯ АРХИТЕКТУРА И ГРАНИЦЫ (CLEAN ARCHITECTURE)

- **ЗАПРЕЩЕНО:** Писать `fetch`-запросы, парсинг данных или логику таймеров напрямую внутри JSX/TSX-компонентов представлений (View Components) [7].
- **РАЗДЕЛЕНИЕ СЛОЕВ:**
  1. **Слой API (`services/api.ts`):** Изолированные функции для работы с HTTP, включающие получение токенов, таймауты и парсинг JSON.
  2. **Слой Хуков (`hooks/use*`):** Инкапсулирует логику жизненного цикла, поллинга и стейт-менеджмента.
  3. **Умные компоненты (Containers):** Получают данные из хуков и передают их вниз. Содержат минимум разметки [8].
  4. **Глупые компоненты (Presentational):** Только принимают `props` и вызывают коллбэки (например, `onGenerateBlock()`). Никакой связи с внешним миром [7].

## 5. СТРОГИЙ TYPESCRIPT

- **ЗАПРЕЩЕНО:** Использовать тип `any`. Применение `any` отключает статический анализ и скрывает проблемы рефакторинга.
- **ОБЯЗАТЕЛЬНО:** Если структура данных неизвестна заранее, применять `unknown` с последующим сужением типа (Type Narrowing) через Type Guards. Для контрактов API описывать строгие интерфейсы и проверять их совместимость.
